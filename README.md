# OnboardAI RAG Assistant — FastAPI Deployment

This project wraps the completed **OnboardAI RAG Assistant over the CPython documentation** assignment as a public HTTP API.

The original assignment used:
- 15 official CPython Tutorial `.rst` pages from the `python/cpython` GitHub repository.
- Fixed-size vs recursive chunking.
- `all-MiniLM-L6-v2` local embeddings.
- FAISS retrieval.
- Source citations using file name + snippet.
- An explicit insufficient-context / "I don't know" path.
- 15 gold Q&A pairs with 100% hit-rate@4 for both chunking strategies in the completed notebook.
- RAGAS evaluation and a hybrid dense + BM25 bonus.

This service uses the **winning recursive strategy** from the assignment: 800-character chunks with 120-character overlap.

## API

### GET `/health`

Shows whether the RAG index is ready.

### POST `/query`

Request:

```json
{
  "question": "How do I handle an exception so my program doesn't crash?",
  "top_k": 4
}
```

Response:

```json
{
  "status": "answered",
  "answer": "...[errors.rst]...",
  "sources": [
    {
      "file": "errors.rst",
      "snippet": "..."
    }
  ]
}
```

For weak retrieval:

```json
{
  "status": "insufficient_context",
  "answer": "I don't have enough information to answer that.",
  "sources": []
}
```

## Structured observability

Every HTTP request and RAG query emits a JSON log event containing useful fields such as:
- timestamp
- level
- event/message
- request path and status
- duration
- question
- retrieval result count
- answer status

This satisfies the required free observability layer without requiring a paid monitoring service.

## Run locally

```bash
python -m venv .venv
```

Windows CMD:

```cmd
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Put your Gemini API key in `.env`, then:

```cmd
uvicorn app.main:app --reload
```

Open:

```text
http://127.0.0.1:8000/docs
```

## Deploy publicly with Render

1. Create a GitHub repository and upload this project.
2. Create a new **Web Service** on Render.
3. Connect the GitHub repository.
4. Render detects `render.yaml` / Dockerfile.
5. Add `GOOGLE_API_KEY` as a secret environment variable.
6. Deploy.
7. Your public API will be available at a URL similar to:

```text
https://onboardai-rag-api.onrender.com
```

The exact URL is generated by Render and cannot be known before deployment.

## Important security note

The original notebook contains a Google API key directly in a code cell. **Do not reuse that exposed key. Revoke/rotate it in Google AI Studio and create a new key for deployment.** The deployed service reads `GOOGLE_API_KEY` from the hosting platform's environment variables instead.

## Optional Langfuse

Langfuse can be added later as a second observability layer. It is not required for the core assignment because structured JSON logs already satisfy the requested observability requirement.
